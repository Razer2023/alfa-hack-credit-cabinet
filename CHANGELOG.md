# Журнал изменений

## Не выпущено

### Добавлено
- Правила командной работы, области ответственности, шаблоны PR и ТЗ.
- Дизайн-правила на основе Core Components Альфа-Банка, THIRD_PARTY_NOTICES.
- Ядро кредитного конвейера (services/core): заявки, статусная модель, журнал событий, JWT-роли, подтверждение и подписание кодом, фоновый конвейер проверок и решения, выдача (мок), SSE-уведомления, очередь и карточка для банка. Docker Compose с PostgreSQL, CI.
- Сервис скоринга (services/scoring): каталог из трёх продуктов, расчёт платежа, балльная карта из 9 факторов, стоп-факторы, ручное рассмотрение, лимит и DSCR, контрпредложение вместо отказа. Правила в версионируемом конфиге.
- docker compose поднимает всю систему: веб, ядро, интеграции, скоринг, PostgreSQL; ядро работает с настоящими сервисами B и C. Сквозная проверка трёх сценариев (deploy/e2e) и CI-задача core-e2e.
- THIRD_PARTY_NOTICES: зависимости веба, сервисов интеграций и скоринга, образы Node.js и nginx.
- Веб-интерфейс целиком: вход по ролям, каталог, мастер заявки с автосохранением и расчётом платежа, подтверждение и подписание кодом, «нужны данные», контрпредложение, трекер и история с живыми обновлениями (SSE), уведомления; очередь и карточка андеррайтера с решением и запросом данных. Типы API генерируются из контракта.
- Скоринг: проверка условий, которые вписал сотрудник банка (S5.4, `POST /offers/check`): рамки продукта, минимальная ставка, лимит по выручке, DSCR, подсказка допустимой суммы. В документации скоринга — SLA и упрощения с обоснованием.

- Ядро: условия, которые вписал сотрудник банка, проверяются скорингом перед подтверждением (S5.4). Менеджер не может выдать условия вне политики, андеррайтер — только с обоснованием (отметка в решении и в истории банка). Эндпоинт `POST /bank/applications/{id}/offer-check` для подсказок в форме.

- S4.9: у заявки есть персональный менеджер — назначается при отправке, клиент видит его контакты в кабинете («Ваш менеджер»), в истории — «Заявку ведёт …».
- S4.6: срок решения по этапам — у статуса обычный срок и время «ждём до», в карточке заявки и в трекере.

- S4.4, S4.7: запрос документов с пояснением, зачем каждый, и загрузка файлов клиентом в кабинете; банк видит статусы и скачивает файлы. Дополнить заявку можно только после загрузки всех документов.

- S2.1: предоценка суммы и шансов по ИНН до подачи заявки — в карточке продукта, без сохранения и без влияния на кредитную историю.

- S6.3: понятная причина отказа — для каждой причины «что можно сделать», кто принял решение, переход к оценке шансов на другую сумму.
- S5.4: подсказки в форме решения сотрудника — проверка условий по политике банка по мере ввода, «Подставить допустимую сумму», запрет для менеджера и обязательное обоснование для андеррайтера при отступлении.

- S4.10: чат по заявке между клиентом и банком внутри кабинета — сообщения приходят сразу (SSE), с уведомлением; в истории заявки не дублируются.

- Документация продукта: User Story Map после интервью со статусом каждой истории и раздел «Развитие» — S3.6, S6.4, S5.5 (NEW) и остальные истории вне MVP, как встроить их в архитектуру.

- S1.2: подбор продукта по цели в каталоге — выбор задачи, необязательные сумма и срок, отметка «Подходит лучше всего» и пояснения по каждому продукту; выбранное переносится в черновик заявки.

- S3.5: подсказки к терминам у клиента — ставка, срок, платёж, переплата, ЕГРЮЛ, ФНС, выписка, поля анкеты компании, простая электронная подпись, кредитная история, контрпредложение. Словарь в `web/src/glossary.ts`; на телефоне подсказка открывается шторкой.

- S8.1: дашборд узких мест для сотрудников банка — время в каждом статусе по журналу событий, медиана и 90-й перцентиль, выход за срок, узкое место; вкладка с демо-массивом сервиса интеграций.

- Правки после демо: цели в подборе продукта — под отрасль клиента по ОКВЭД; из расчёта платежа убрана переплата; менеджер и чат — одной карточкой внизу заявки клиента; запрос данных и документов у клиента — одним блоком и одним запросом.

### Изменено
- Скоринг: контрпредложение считается по классу риска предлагаемой суммы — предоценка без суммы и с суммой показывает один максимум и ставку; при отказе по низкому баллу клиент видит два главных фактора (S6.3).
- Веб: каталог продуктов приведён к оформлению обзора — белые карточки, фирменный знак, крупные суммы и красные кнопки оформления. Наведение и фокус с клавиатуры выделяют карточку красным контуром; анимация учитывает настройку уменьшения движения.
- Веб: фирменный красный акцент с фоновой «А», следующий шаг по состоянию заявки, обзор с трекером и отдельный каталог продуктов; адаптивная шапка и карточка заявки на Core Components.
- Кредит не одобряется автоматически: рекомендацию скоринга «одобрить» или «другие условия» подтверждает менеджер или андеррайтер (статус PENDING_APPROVAL). Автоматически остаются отказ по стоп-факторам и передача рисковых заявок андеррайтеру; менеджер может передать заявку андеррайтеру.

### Исправлено
