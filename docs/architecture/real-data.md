# Переход с синтетических данных на настоящие

Прототип по условиям кейса работает только на синтетических данных и без доступа к системам банка. Архитектура построена так, чтобы настоящие источники подключались **за теми же контрактами**: ядро (A) и веб (D) при этом не меняются. Меняются адаптеры в сервисе интеграций (B), правила в сервисе скоринга (C) и несколько настроек ядра.

```
веб (D) → ядро (A) ──→ интеграции (B) ──→ ЕГРЮЛ, ФНС, БКИ, выписка, хранилище файлов
                  └──→ скоринг (C)    ──→ правила, откалиброванные на портфеле банка
```

## Порядок перехода

1. **Тестовый контур.** Получить у банка доступы к тестовым версиям источников и тестовые ИНН. Синтетические данные оставить для локальной разработки и CI.
2. **Адаптеры в сервисе B.** Для каждого источника — модуль рядом с текущим (`companies.py`, `enrichment.py`, `documents.py`), выбор источника — переменной окружения сервиса, по умолчанию — синтетика. Ответы привести к схемам `contracts/integrations.yaml`; контракт не менять, иначе нужен PR в ядро.
3. **Скоринг.** Откалибровать `scorecard.yaml` на портфеле, обновить `products.yaml`, поднять версии правил.
4. **Ядро.** В `.env` контура:
   - `CORE_INTEGRATIONS_MODE=http`, `CORE_SCORING_MODE=http` и адреса сервисов (`CORE_INTEGRATIONS_URL`, `CORE_SCORING_URL`);
   - `CORE_DEMO_CODES=false`;
   - новый `CORE_JWT_SECRET` — не короче 32 символов, только из хранилища секретов;
   - `CORE_PIPELINE_STEP_DELAY_SECONDS=0` — пауза нужна только для демо.

   Вход — через SSO банка вместо пароля, выдача — через АБС.
5. **Проверка.** Прогнать `deploy/e2e/scenarios.py` на тестовых ИНН. Тесты ядра с `http` сейчас ждут цифры заглушки: 7 тестов нужно перевести на проверку фактов — см. `tz/A-core/2026-10-25-c-scoring-followups.md`, пункт 3.
6. **Включение.** Сначала для сотрудников банка (рабочее место, дашборд), затем для клиентов.

## Требования, которые появятся с настоящими данными

- **Персональные данные и банковская тайна** (152-ФЗ, 395-1): данные клиентов только в контуре банка, доступ по ролям, журнал доступа. Сейчас журнал событий ядра уже фиксирует действия по заявке.
- **Согласие на запрос кредитной истории** (218-ФЗ): текст согласия — на шаге отправки заявки, рядом с подтверждением кодом. Без согласия ядро не должно запрашивать БКИ.
- **Секреты** — только в хранилище секретов банка. `.env.example` содержит только dev-значения и в продуктиве не используется.
- **Отказоустойчивость.** Таймаут внешних вызовов — `external_timeout_seconds` (5 с). Если B или C недоступен, ядро отвечает 503 «Сервис временно недоступен». Шаги конвейера повторяются, а проверка условий сотрудника не блокирует решение, а предупреждает. Для медленных источников (бюро) — кэш ответа на заявку и повтор по расписанию.
- **ИИ.** Как и сейчас, без ИИ основной сценарий работает. Если понадобятся LLM, то только модели с открытыми весами внутри контура банка.
