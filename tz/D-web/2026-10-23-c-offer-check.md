# Подсказки в форме решения: потянет ли компания условия

## Зачем
В форме подтверждения (`DecisionForm`) сотрудник может поменять сумму, срок и ставку. Скоринг теперь умеет проверять, проходят ли эти условия политику банка, и подсказывать допустимую сумму. Хорошо бы, чтобы сотрудник видел это сразу, пока вводит условия, а не узнавал из ошибки после нажатия кнопки.

## Что нужно сделать
Зависит от ТЗ Артёму `tz/A-core/2026-10-23-c-offer-check.md`: там появится `POST /bank/applications/{id}/offer-check`.

1. Когда меняются сумма, срок или ставка, вызвать `offer-check` с небольшой задержкой (300–500 мс после ввода).
2. Показать результат под полями:
   - `allowed: true`, проверок нет → тихая зелёная отметка «Условия в рамках политики банка», рядом платёж `monthly_payment` и `DSCR`;
   - `checks` с `level: "error"` → красный блок со списком `checks[].text`;
   - `level: "warning"` → жёлтый блок, подтверждению не мешает.
3. Если есть `suggestion` — кнопка «Подставить {suggestion.amount} ₽». Она заполняет сумму, срок и ставку из подсказки.
4. Кнопка подтверждения:
   - у **менеджера** неактивна, пока есть ошибки (рядом — «Передать андеррайтеру»);
   - у **андеррайтера** активна, но при ошибках поле комментария становится обязательным, с подписью «Обоснуйте отступление от кредитной политики».
5. Если сервер всё-таки ответил 422 `offer_not_allowed` или `override_comment_required`, показать его текст.

## Пример (если это API)
```http
POST /api/v1/bank/applications/{id}/offer-check
{"amount": 10000000, "term_months": 12}
```
```json
{
  "allowed": false,

  "suggestion": {"amount": 2600000, "term_months": 12, "rate": 18.9},
  "metrics": {"dscr": 0.46, "min_dscr": 1.25}
}
```

## Готово, когда
- [ ] Менеджер вводит СтройМонтажу 10 млн на 12 мес. → красное «Компания не потянет платёж…», кнопка неактивна, есть «Подставить 2 600 000 ₽»
- [ ] Рекомендованные условия без изменений → зелёная отметка, подтверждение как раньше
- [ ] Андеррайтер с ошибками может подтвердить только с комментарием
