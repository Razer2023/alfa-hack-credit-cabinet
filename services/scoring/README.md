# Скоринг и кредитное решение (область C)

Сервис отвечает на вопрос «давать ли кредит и на каких условиях». Ядро вызывает его на шаге `SCORING` и получает решение, балл, факторы для андеррайтера, причины для клиента и предложение.

| Эндпоинт | Story | Что делает |
|---|---|---|
| `GET /api/v1/products`, `GET /api/v1/products/{code}` | S1.1 | Каталог из трёх продуктов |
| `POST /api/v1/calc/payment` | S3.2 | Аннуитетный платёж, переплата |
| `POST /api/v1/decisions` | S5.1, S5.2, S6.1 | Балльная карта → кредитная политика → решение и оффер |
| `GET /health` | — | Healthcheck, версия правил |

Контракт: [contracts/scoring.yaml](../../contracts/scoring.yaml), генерируется из кода командой `python -m app.export_docs`.

## Запуск

```bash
uv sync
uv run uvicorn app.main:app --port 8001   # Swagger: http://localhost:8001/docs
uv run pytest -q
```

В Docker сервис называется `scoring` и слушает порт 8000. Ядро переключается на него переменной `CORE_SCORING_MODE=http`.

## Правила — в конфиге, а не в коде

Все числа лежат в двух файлах:

- [rules/products.yaml](rules/products.yaml) — продукты, лимиты сумм и сроков, базовые ставки;
- [rules/scorecard.yaml](rules/scorecard.yaml) — факторы и баллы, классы риска, стоп-факторы, триггеры ручного рассмотрения, параметры платёжеспособности, тексты причин.

Версии обоих файлов уходят в ответ как `model_version` (`scorecard-1.0+products-1.0`) и сохраняются в заявке. По любому решению видно, по каким правилам оно принято. Конфиг проверяется при старте: если в нём ошибка, сервис не запустится, а не примет неверное решение. Папку с правилами можно подменить без пересборки образа (`SCORING_RULES_DIR`).

## Как принимается решение

Порядок повторяет классический кредитный конвейер для МСБ: сначала дешёвые проверки, которые сразу дают отказ, потом оценка риска, в конце расчёт суммы, которую компания может обслуживать.

```
Стоп-факторы ──отказ──▶ REJECT
     │
Условия продукта (мин. сумма) ──▶ REJECT
     │
Триггеры ручного рассмотрения ──▶ MANUAL_REVIEW
     │
Балльная карта → класс риска
     ├─ D ──▶ REJECT
     ├─ C ──▶ MANUAL_REVIEW
     └─ A, B
          │
     Лимит по выручке + DSCR
          ├─ запрос проходит ──▶ APPROVE (запрошенные условия)
          ├─ та же сумма на срок длиннее ──▶ COUNTER_OFFER
          ├─ меньшая сумма на макс. срок ──▶ COUNTER_OFFER
          └─ не тянет даже минимум продукта ──▶ REJECT
```

### 1. Стоп-факторы → отказ

| Условие | Почему |
|---|---|
| Компания не `ACTIVE` в ЕГРЮЛ или в ликвидации | Юрлицу, которое прекращает деятельность, кредит не выдаётся |
| Бизнесу меньше 6 месяцев | Нет истории оборотов, оценить устойчивость нельзя |
| Просрочка в БКИ больше 90 дней | Дефолт по определению Базеля и ЦБ |

### 2. Ручное рассмотрение

Эти сигналы не означают отказ сами по себе, но у них часто есть объяснение, которого нет в данных: техническая просрочка, спор с налоговой, офис в бизнес-центре с сотнями арендаторов. Поэтому решение принимает андеррайтер, даже если балл высокий.

- просрочка 31–90 дней;
- задолженность по налогам;
- адрес массовой регистрации;
- нет данных о выручке или кредитной истории.

### 3. Балльная карта (S5.1)

Балл = 520 + сумма баллов факторов, шкала 300–900, как у бюро кредитных историй. У каждого фактора есть корзины значений с баллами. Это стандартная форма скоринговой карты: её легко объяснить клиенту и аудитору, в отличие от «чёрного ящика».

| Фактор | Корзины → баллы | Логика |
|---|---|---|
| Возраст бизнеса | <1 г. −40 · 1–2 г. 0 · 2–3 г. +20 · 3–5 лет +40 · ≥5 лет +60 | Большая часть малых бизнесов закрывается в первые годы |
| Годовая выручка | <6 млн −20 · 6–20 млн +10 · 20–60 млн +30 · ≥60 млн +50 | Масштаб и запас прочности |
| Макс. просрочка в БКИ | 0 +60 · 1–30 дн. 0 · 31–60 −80 · 61–90 −120 · >90 −200 | Самый сильный предиктор будущих просрочек |
| Действующие кредиты | 0–1 +20 · 2 +10 · 3 0 · ≥4 −30 | Много кредитов — признак кредитования «с кредита на кредит» |
| Долг к выручке | <10 % +40 · 10–25 % +20 · 25–40 % −10 · ≥40 % −60 | Текущая долговая нагрузка |
| Запрошенная сумма к выручке | <20 % +30 · 20–35 % +10 · 35–50 % −20 · ≥50 % −50 | Насколько кредит соразмерен бизнесу |
| Сотрудники | <5 −10 · 5–14 +10 · ≥15 +20 | Устойчивость операционной модели |
| Долг по налогам | нет +10 · есть −40 | Платёжная дисциплина |
| Массовый адрес | нет 0 · да −50 | Риск номинальной компании |

Каждый фактор возвращается андеррайтеру с баллом и значением (`"8,4 г."`, `"11,7 %"`), поэтому видно, из чего сложилась оценка.

| Класс | Балл | Решение | Лимит, доля выручки | Ставка |
|---|---|---|---|---|
| A | ≥700 | автоматически | 35 % | базовая −1 п. п. |
| B | 620–699 | автоматически | 25 % | базовая |
| C | 540–619 | андеррайтер | — | — |
| D | <540 | отказ | — | — |

Ставка зависит от риска (risk-based pricing): надёжный клиент получает скидку.

### 4. Платёжеспособность: лимит и DSCR (S5.2)

Одного хорошего балла мало: компания должна физически тянуть платёж.

- **Лимит** = выручка × доля класса, но не больше максимума продукта.
- **Свободный денежный поток** = 20 % среднемесячного оборота по счёту.
- **Платёж по текущим долгам** ≈ 4,5 % долга из БКИ в месяц (оценка, в БКИ нет графиков).
- **DSCR** = свободный поток / (текущие платежи + новый платёж) ≥ 1,25. Это типовой ковенант банков для МСБ: на каждый рубль платежа должно приходиться 1,25 ₽ свободных денег.

### 5. Контрпредложение вместо отказа (S6.1)

Если запрос не проходит по лимиту или DSCR, сервис не отказывает, а ищет условия, которые компания потянет:

1. **Та же сумма на больший срок.** Минимальный срок из ряда кратных 6 месяцам, при котором DSCR соблюдён. Клиент получает нужные деньги, платёж меньше.
2. **Если не помогает и максимальный срок** — максимальная сумма на максимальный срок продукта, округлённая вниз до 100 000 ₽.
3. **Если и она меньше минимума продукта** — отказ с понятной причиной.

Причины (`reasons`) написаны для клиента человеческим языком, коды — для аналитики и экрана андеррайтера.

## Упрощения прототипа

- Веса карты экспертные, не обучены на данных: реальной истории дефолтов у команды нет. В продуктиве их калибруют логистической регрессией по выборке выданных кредитов, формат карты при этом не меняется.
- Свободный поток считается как доля оборота, а не по управленческой отчётности. Платёж по текущим долгам оценивается по сумме долга.
- Ставка зависит только от класса риска, без учёта залога, поручительства и срока.
